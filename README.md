# 音频实时转字幕

一个项目、一个入口（`run.bat`）。**一份引擎，两个界面共享**：

- **浏览器控制中心**（推荐）：采集 + 识别 + 翻译只跑**一份**，同一个页面里
  设置一切（含桌面悬浮窗的外观），并可一键唤起悬浮窗
- **桌面悬浮窗**：置顶、镂空透明、可拖动，**双语按条绑定**显示（原文+译文永不拆散）；
  只以**跟随模式**运行——通过本机 HTTP 从控制中心拉字幕，**不重复占声卡、不重复跑 Whisper**

纯本地识别，音频不上传；翻译仅在开启时把识别出的**文字**发给所选翻译后端。

> 桌面悬浮窗的**独立运行模式已移除**：它现在只跟随控制中心（共用一份引擎/音频/模型）。
> 想要字幕窗口，启动控制中心并在左侧勾选「启用桌面悬浮字幕窗」即可；字号/字体/颜色/特效
> 也在控制中心左侧统一设置（默认 **黑体 20 号**）。

## 快速开始

```bat
run.bat        REM 菜单：1 浏览器控制中心（推荐） / 2 自检设备 / 0 退出
run.bat web    REM 直接进浏览器控制中心
run.bat check  REM 只做设备自检（列出回环/麦克风）
```

浏览器控制中心的使用流程：
1. 选**采集源**（系统声音=给播放的视频配音幕 / 麦克风=说话），默认自动检测
   哪个输出设备真正在出声
2. 选**推理设备 / 识别模型 / 识别准确度**（听不准优先按这条链升：均衡 → small → GPU+large-v3）
3. 选**翻译后端**（在线免费 / 百度 / OpenAI 兼容 DeepSeek·通义·智谱·GPT / 不翻译）
4. 勾**启用桌面悬浮字幕窗**，调字号/颜色/特效/条数（改设置即时重启悬浮窗）
5. 点**开始** → 网页与悬浮窗同时出双语字幕；底部导出**双语 SRT / TXT**
6. 开始之后**关掉浏览器页也无妨**：识别在后台线程继续，悬浮窗继续出字幕
7. 手上有**视频文件**要传云端 / 出成片字幕：页面最下面「本地视频 → 16k 单声道 WAV」
   （抽音轨、按云端上限切段），或直接点「不提取，本机识别出双语字幕」

## 分发给别人 / 新机器首次运行

在你这台机器上打包：

    .venv\Scripts\python pack_release.py        REM 生成 dist\audio-live-caption-<日期>.zip（约 0.1 MB）

打包用的是**白名单**：只带根目录里的源码/文档/`run.bat`，不认识的一律不进包；
单个文件超过 1 MB 或必需文件缺失会**直接拒绝出包**（不是悄悄收进去）。所以这些都不会带上：

| 不带 | 为什么 |
| --- | --- |
| `.venv/`（约 3.1 GB） | 跟机器和 Python 版本绑定，换机器就是废的；对方首次运行会自动重建 |
| `models/`（约 2.3 GB） | 权重按需自动下载（本机实测 base 282 MB、small 464 MB、medium 1.4 GB） |
| `records/` | 你的**录音留档**，隐私 + 体积（本次一份就 72 MB） |
| `overlay_pos.json` | 悬浮窗位置记忆，属于"你这台机器的桌面状态" |
| `__pycache__/ .tmp/ dist/` | 构建产物、临时文件 |

对方拿到 zip 只要两步：

1. 装 **Python 3.10~3.12**（安装时勾 **Add python.exe to PATH**；微软商店那个 `python`
   壳不行 —— `run.bat` 会写明这个失败原因）。本机用的是 3.12.10。
2. 把 zip **解压成一个文件夹**，双击 `run.bat`：首次会自动建 `.venv` 并装依赖
   （要联网，几分钟），装完直接进控制中心。不用再敲任何命令。

需要联网的只有两处：**首次装依赖**和**首次下载所选模型权重**。之后识别、整篇精修、
繁→简全部离线；只有翻译选云端后端时才需要网络（选"不翻译"或本地 argos 就离线）。

- GPU 可选：没有 N 卡或缺 CUDA 12 运行库会自动退回 CPU 并在页面写明原因（不装也能跑）。
- 系统声音回环是 **Windows 专属**（WASAPI）；macOS/Linux 只能用麦克风。
- 默认只装 `faster-whisper`：`openai-whisper` 会拖进约 2 GB 的 PyTorch，已改成
  可选注释（想做对比实现再手动装），代码里两者都有就都显示、没有就自动少一项。
- 发包时把 `pack_release.py` 打印的 **SHA256** 一起给对方，让他确认下载没被改/没坏。

验证包是否可用（不用换机器就能查大部分问题）：解压后在该文件夹里跑

    python -m compileall .                       REM 语法
    python -c "import app, desktop_caption, polish, han_convert"   REM 导入闭环


## 延迟已到 ~1 秒档（本轮 ①②③）

| 优化 | 效果 |
| --- | --- |
| ① 换 **faster-whisper**（int8 量化，CTranslate2） | 同一 base 模型，推理快约 9 倍：实测 11s 音频 1.0~1.2s 识完（RTF≈0.1），4s 窗口推理仅 0.1~0.3s；仍是纯本地。`openai-whisper` 保留为可选后端 |
| ② **VAD 语音段判停**（可选，默认关） | 每约 1 秒对最近 1.4s 音频做一次轻量解码，用"语音段是否还在窗口尾部"判断说完没——BGM/音效让 RMS 电平一直高时也能早触发。实测多数场景关闭它延迟更低（探针占用算力），故**默认关闭**，仅在网页勾选启用 |
| ③ **语种自动重检测**（自动检测模式下） | 不再"第一句定终身"：探测窗口持续检测语种，内容中途换语种（如英剧换日剧）连续 2 次确认后自动切换，悬浮窗/网页提示「语种自动切换：ja」 |
| ④ **半句缝合**（默认开，原位修订） | 早触发偶尔把一句话切成两条（`"They must move." + "As one."`）。按词法线索把后半句**并回上一条且沿用其条目号**：网页与悬浮窗原位变成整句、旧半句的译文作废重出，首条显示延迟一点不加 |
| 　└ 词库 | 装了 `zhconv` 就用它（OpenCC 词库 + 词级校正）；没装自动退回内置 288 字对照表 —— 侧栏与「卡住时自查」快照里都会写明当前用的是哪套。 |
| 语言检测缓存 | 冷启动首见高置信即钉语种，后续正式窗口不再重复 detect |

感知延迟 ≈ 句尾停顿 0.6s + 推理 0.1~0.3s + 刷新 ≤0.4s → **整句说完约 1~2 秒出原文**，
译文随后 1~2 秒原位补上。实测数字可用 `test_faster_real.py` 复现。

**日语支持**：识别原生支持（`--language ja` / 网页选日本語，自动检测下也会自动跟随）；
看日语视频建议 `small` 以上更准（faster-whisper int8 下 base 已能实时追日语）。

## GPU 推理（本机已打通，附实测数据）

左侧「推理设备」默认**自动**：看得见 NVIDIA 显卡且 CUDA 12 运行库真能加载就走 GPU，
否则安静回退 CPU 并在页面写明原因（同一进程只提示一次）。"能用"的判定不是"模型构造
成功"——CTranslate2 缺库时要到**第一次推理**才炸，所以加载阶段真跑一次 0.5 秒探测
（探测必须关 VAD，否则静音被 VAD 短路，探测通过是假的）。

实测（RTX 2060 6GB / 驱动 546.33，faster-whisper，准确度=均衡 beam5）：

| 模型 | GPU 单窗(4s) | GPU RTF | CPU(int8) 单窗 | CPU RTF |
| --- | --- | --- | --- | --- |
| base | 0.06s | 0.018 | 0.47s | 0.055 |
| small | 0.12s | 0.024 | 1.49s | 0.167 |
| medium | 0.27s | 0.045 | **4.16s → 超过窗长，必然积压** | 0.455 |

结论：**GPU 不是为了让 base 更快**（CPU 早就 8~10 倍实时，根本不缺），GPU 的价值是
medium 这一档在 CPU 上追不上实时、上 GPU 只吃掉窗口的 7%。想提准确率就得换大模型，
换大模型就得有 GPU。

装运行库，**版本要配驱动**（先 `nvidia-smi` 看右上角 "CUDA Version"，本机
546.33 → 12.3）：

```bat
.venv\Scripts\pip install "nvidia-cublas-cu12==12.3.4.1" "nvidia-cudnn-cu12==9.0.0.312"
```

踩过的坑：装最新的 12.9.2.10 + 9.25.1.1，CUDA 模型能构造，但第一次推理直接把进程
干崩（`0xC0000005`），换 float32 / int8_float16、去掉 cuDNN 都一样 —— 12.9 的库和
12.3 时代的驱动不配套。降到与驱动同号的 cublas 12.3.4.1 + cuDNN 9.0.0.312 就通了
（或者升级显卡驱动，那是另一回事）。

第二个坑：pip 装完 CT2 依旧报 `Library cublas64_12.dll is not found`。因为 CT2 用普通
LoadLibrary **按文件名**找库，而 `os.add_dll_directory` 登记的目录只对带
`LOAD_LIBRARY_SEARCH_USER_DIRS` 标志的加载生效。代码已改成**按绝对路径先 ctypes 预加载**
`site-packages\nvidia\*\bin`（机器上别处有现成 DLL 就写进环境变量 `ALC_CUDA_BIN`，
分号分隔，同样生效），加载过一次后 CT2 按名字就能命中。

## 整篇精修重识别（离线：拿录音换准确率）

实时字幕为了抢时效必须做的四件事，全是"准"的代价：4 秒切窗、句子没说完就早触发
flush、每窗独立解码（`condition_on_previous_text=False`）、卡顿时丢最旧音频。

勾选「保留本次录音（供整篇精修重识别）」后，引擎会把**送进模型之前**那份 16kHz 单声道
音频同步写成 `records/session-*.wav`（一小时约 115MB；被实时链路丢掉的音频也在里面）。
点「停止」后页面出现「整篇精修重识别」：整段音频一次喂给模型 —— 不切窗、跨句上下文、
解码临时切「高精度」、还能临时换 small/medium/large-v3 —— 另出一份精修字幕，单独导出
双语 SRT/TXT，实时那份一个字都不动。GPU 上整篇跑一分钟音频只要几秒；纯 CPU 也能跑，
就是慢（离线嘛）。实测 11 秒 jfk 样本：GPU 上整篇 0.29 秒出结果。

整篇解码有个副作用：它爱把三五句合成一个 10 秒长段（成片字幕一条挂 10 秒没法看）。
`polish.refine_segments` 会按标点把它重切回 6 秒 / 13 词以内的字幕行 —— 先句末标点、
再句中标点、都没标点才按长度硬切，时间轴按字符比例分配；带 25% 余量，所以反复 refine
结果不变（幂等，不会每轮都在抖）。

去 BGM 的正解也在这条路上：实时链路里做人声分离必然爆延迟，但精修阶段跑分离模型
不影响任何人的实时性。

## 本地视频 / 音频 → 16k 单声道 WAV（给云端大模型）

实时链路只能"听声卡"，而云端 ASR / 多模态模型要的是**文件**。控制中心最下面那张卡片就是把本地
视频（mp4/mkv/mov/webm/m4a/mp3/wav…）的音轨抽成 **16kHz / 单声道 / 16bit PCM WAV** —— 这正是
Whisper 系内部使用的格式，云端拿到不用再转码。

- 体积账：16k 单声道 16bit = 32KB/s ≈ **1.8MB/分钟**（一小时 115MB）。选完文件页面就报时长、
  轨道和导出体积预估，先看清楚再决定切不切段。
- **默认按 24MB 切段**：多数云端转写接口有 25MB 上限（OpenAI Whisper API 就是），切段后每个
  文件都能直接上传；填 0 = 不切段。44 字节的 RIFF 头也算进上限里。
- 只抽中间一段也行（起始秒 / 时长秒）。输出目录留空 = 视频所在目录；同名文件绝不悄悄覆盖
  （自动加 `-1` 序号），失败时留下的半个文件会清掉。
- 解码靠 **PyAV**（`faster-whisper` 自带的依赖，wheel 里就有整套 FFmpeg 库，
  **不需要装 ffmpeg.exe**）。只有外部 ffmpeg 的机器自动走子进程兜底（可执行文件全路径放
  `ALC_FFMPEG`）；两个都没有时页面直接说要装哪个，实时识别不受影响。
- 「浏览」弹的是系统文件框（Tk）；远程桌面/无桌面会话弹不出来时，设环境变量 `ALC_PICK`
  = 要处理的文件全路径，按钮会直接用它的值（也方便脚本化）。
- 卡片上另有「不提取，直接本机识别出双语字幕」：把视频整段喂给本机模型跑精修 ——
  `polish` 读音频用的就是这一个模块，所以"网课视频 → 双语 SRT"一步到位，不用先转格式。
- 速度：只解音轨不解画面，一小时视频一般几十秒内跑完（后台线程做，界面不卡）。

## 试过并且不划算的路（别再试）

- **实时谱减/降噪前置去 BGM**：写过纯 numpy 的谱减+软掩蔽（4 秒窗约 5~10ms），
  按等 SNR 扫参实测对识别**没有收益、噪声一大反而更差**（平稳配乐 0dB：错误率 9%→9%；
  −4dB：23%→32%；背景人声 0dB：82%→82%/95%）。原因是 faster-whisper 已有 Silero VAD 门，
  模型本身就在脏音频上训练过，而谱减啃出来的"水下/金属"伪影它更不认。已删除。
- **实时链路里做人声分离**（demucs/UVR）：权重 2GB 级、RTF 常在 1~3，塞进 4 秒窗口
  延迟必爆。真要用只能做成"停止后离线精修"（保留整段录音 → 分离人声 → 大模型整篇重识别
  → 导出精修 SRT），实时字幕不受影响 —— 这条路还没实现。
- **桌面悬浮窗独立跑一份引擎**：会和控制中心抢声卡/模型，已移除，改为纯渲染跟随。

## 字体显示

- 默认特效是**单向淡影**（浅灰偏移 2px）——不再是四向黑副本叠出来的"黑影块"
- 右键菜单可循环切换 阴影→描边→无；白/黄/青/绿/粉字色；字号±；显示条数
- **位置会记住**：拖到哪儿，下次启动（含控制中心重开悬浮窗）就回到哪儿；记忆存在
  `overlay_pos.json`。若那个坐标已不在任何屏幕上（拔掉副屏等），会自动回默认位置，
  不会出现"窗口跑到看不见的地方"。右键 **回到默认位置（清除记忆）** 可手动复位。
- **黄色提醒**（语种切换提示、BGM 自救提示、界面错误等）画在**字幕正上方**并让出高度，
  出现/消失时字幕块不会上下跳。
- 原文白色、译文黄色（颜色都在网页上可选），一条字幕的原文+译文**绑定在同一块**，
  译文晚到就原位补上，永不与其他句子错排

## 手动连接悬浮窗（可选）

正常无需手动启动——控制中心左侧勾选「启用桌面悬浮字幕窗」会自动带起并传好外观参数。
想手动连到某个端口（端口显示在控制中心页面左侧），或改外观：

```bat
.venv\Scripts\python desktop_caption.py --follow http://127.0.0.1:54321 --font 黑体 --font-size 20
.venv\Scripts\python desktop_caption.py --check    REM 只列出回环/麦克风设备
```

窗口操作：**左键拖动** · **右键菜单**（字号/特效/颜色/置顶/条数/回到默认位置/退出）· **Esc** 退出。
导出双语 SRT/TXT 在控制中心页面底部。

## 翻译后端（`--provider` / 网页下拉框）

| 后端 | 需要 | 说明 |
| --- | --- | --- |
| `none` | — | 不翻译，只显原文 |
| `translators` | 联网 | 免费在线（bing/google/腾讯…自动回退），本机实测已译出中文 |
| `openai` | api_key | 任意 OpenAI 兼容接口：DeepSeek、通义、智谱、GPT… |
| `baidu` | appid/secret | 百度翻译开放平台 |
| `argos` | 离线+下模型 | `pip install argostranslate`，首次下载 en→zh 模型 |

后台线程翻译、带缓存与超时；失败自动回退显示原文。
`openai` 后端会**自动带上上一句作为上下文**，习语/断句理解显著变好
（如 "stiff upper lip" 不会再直译成"坚硬的嘴唇"）。

## 工作原理

```
sounddevice(麦克风) / PyAudioWPatch(WASAPI loopback 系统声音，按设备抓)
        │ 回调线程 48k 立体声 → 降混 → 重采样 16k → 滚动缓冲(背压丢最旧)
        ├─ VAD 探针：每~1s 解码最近 1.4s → 判"说完没"+语种漂移票
        ▼
VAD/RMS 判停 0.6s 早触发 / 满窗送检 → RMS静音门限 → faster-whisper(int8)
        ▼                     ┌→ 浏览器页面（每1s局部刷新）
后台分发线程 → 字幕服务(HTTP: rev增量/epoch重置) ─┤
（同进程翻译线程→上一句上下文翻译→原文+译文绑定）  └→ 桌面悬浮窗 --follow（400ms 拉一次）
```

- 回环用**回调流**而非阻塞 `read()`：静音时 WASAPI 不产数据，阻塞读会永久卡死。
- 悬浮窗**不碰音频也不跑模型**（纯渲染跟随），声卡共享模式实测多进程同开也没问题，
  但现在只有一份引擎在采集，天然无冲突。

- 引擎统计「**过了静音门却零字**」的连续窗数，到 3 窗就自动调用 `set_non_speech_filter(False)`
  把两道过滤一起关掉，之后正常出字幕；同时提示

## 常见问题

**中文音频出来的字幕是乱的，甚至变成日文** — 是语种被钉错了，不是识别力不行。Whisper 在
**静音 / 纯 BGM 的窗口里会幻觉出「日本語字幕」这类片尾字幕**，而且自报的日语置信度还很高；
早期规则是“首见即钉”，中文音频就这样一票钉成日语，之后整场都用日语解码 → 必然错乱。
现在的语种投票规则：

① 没有有效文本（空、纯标点、命中幻觉名单）的窗口**不投票**；
② 文字脚本优先于模型自评 —— 出现假名一定判日语（中文里不会出现假名）；“汉字且无假名”
   则在模型自报 <0.90 时纠回中文（纯汉字的日语句子留给模型）；
③ 冷启动要**连续 2 票**一致才钉语种；④ 中↔日这一对切换要 **3 票**（最容易互翻），票不连续
   立刻清零；⑤ 你在左侧显式选了语言，以上全部忽略、全程钉死。

顺带修掉一件事：**原文已经是中文就不再机翻**。本项目目标语言本来就是中文，“中文翻中文”只会
丢标点、乱语序（第二行“译文”其实是原句残骸），还白等一个网络往返。现在翻译器一次都不会被调用，
悬浮窗只出一行。例外：语种是**粤语**时照翻 —— 汉字写法但需要转成普通话。最省心的做法：
左侧「语言」直接选**中文**。

**日语到中文不准** — 按影响排序：① **语言选「日本語」钉死**（4 秒短窗对日语很不稳：真日语的
自报置信度经常只有 0.5，而旧门槛 0.7 会把正确的票整张丢掉，语种就一直停在错的那边；现在门槛
0.45 + 假名硬证据，但钉死仍是最准的）；② `base` 的日语明显弱于英语，GPU 上换 `small`/`medium`
（见上面 GPU 实测表；CPU 上 medium 追不上实时）；③ 日语术语、外来语的片假名写法用**热词**
喂进去，例 `サーバー, Kubernetes, 負荷試験`。日语原文照旧会翻成中文。

- 状态行出现 **`异常跳过 N 次`** → 某窗数据把线程打炸过一次，程序已经自己接着跑了；
- 状态行出现 **`分发已自愈 N 次`** → 分发线程（把识别结果搬上屏幕的那条）偷偷退出过，界面已经
  自动把它续上了。这条计数就是"曾经卡过"的证据，出现非 0 请把快照告我 —— 引擎活着但字幕不动
  基本都是它；
- 状态行下方那行**灰色代码框**就是栈尾（`File caption_engine.py line NNN ← 异常类型: 说明`），
  把这行告我就能定位；同时它会写进 `store.status["error"]`，悬浮窗和网页都能看到；
- 出现黄条 **`识别追不上音频：已积压 Ns`** → 不是死，是模型/档位对你这台机器太重（例如 CPU 上跑
  medium/large-v3）。有 GPU 就把设备切到 GPU（或「强制 GPU」），或把模型降一档。

（悬浮窗那侧本来就是安全循环：它自己出错会把 **`界面错误：…`** 直接画在窗口上。看到那行字
说明问题在悬浮窗，不在识别链路。另外顺手确认过：本机磁盘没满，不是写不下录音导致的。）

**一句话被切成两条字幕（中文跟着断句也变味）** — 例：`They must move.` + `As one.`。
低延迟靠"停顿 0.6 秒就提前送检"，切句是它的固有代价，所以默认开了**半句缝合**：判断依据
不是标点（Whisper 会给每个窗口都补句号），而是词法线索——后条以 ``as/for/to/of/and/but/
that/which`` 这类"几乎不可能开启新句"的接续词开头，或前条以冠词/介词/助动词等**悬空词**收尾。
命中就并回上一条（**同一条目号 → rev+1 的原位修订**），译文随即按整句重出。
宁可少并也不误并：真句尾（`!?。！？…`）、后条开头不是接续词、中文这类无词边界的语种都不并。
要是你把两句正常的话看到被粘成一句，取消左侧「自动缝合被切断的半句」即可（停止→开始生效）。
状态行会显示"缝合 N 处"，方便确认它有没有在干活。

**识别偶有听错词（the females 听成 the funeral）** — 三个杠杆，按性价比排序：

① **识别准确度**（默认「均衡」= Whisper 官方 beam=5）：早期版本为压延迟把解码写死成贪心
（beam=1），而贪心一旦在某个词上选错就没有回头路，近音词/生僻词最容易翻车。本机实测
beam=5 与贪心延迟相同（11s 音频 1.16s 识完，RTF≈0.11），所以默认已改回官方档。算力真紧
（换 medium、多路并发压满 CPU）时才降「速度优先」；顽固错句可临时用「高精度」（beam=10，
约慢 20%）。
② **热词 / 提示词**：把反复听错的人名、术语、话题词填进左侧输入框（例
`females, gorilla, hierarchy`），它作为 Whisper 的 initial_prompt 引导解码，不会出现在字幕里。
faster-whisper 1.1+ 已移除 hotwords 参数，这是当前唯一可用的词汇引导手段。
③ **识别模型** 换 `small` / `medium`：近音词错误的根本解药，代价是延迟按比例上升
（int8 下 base RTF≈0.1 → small≈0.3，仍远高于实时）。

改档位/热词不用重新下载模型，停止 → 开始即生效。

**背景有配乐/噪声，采集不准** — 按性价比排序，前三步都不用装东西：
① 先分清是"听不准"还是"句子被切断"（后者见上面两条 FAQ，缝合已默认开）；
② 换模型 `base`→`small`→`medium`（本机 CPU 实测单窗 0.47s→1.49s→4.16s，
`medium` 在 CPU 上**已经追不上 4 秒实时**，会积压）；
③ 有 NVIDIA 显卡就按「GPU 推理」那节装上运行库，然后 `medium` 单窗只要 0.27s；
④ 停止后点「整篇精修重识别」，把实时丢掉的跨句上下文和整句切分全补回来。
真·去 BGM（demucs/UVR 人声分离）只适合放在 ④ 之前跑：实时链路里跑它必爆延迟，
且要 2GB 级权重。**这条还没做** —— 需要的话再说，别指望实时去伴奏。

**手上有视频文件，想丢给云端模型转写** — 页面最下面「本地视频 → 16k 单声道 WAV」：抽音轨成
16k/单声道/16bit PCM（约 1.8MB/分钟），默认按 24MB 切段 —— 多数云端接口有 25MB 上限（OpenAI
Whisper API 就是），切完每个都能直接传；只想传中间一段就填起始/时长秒。云端还嫌大就把「每段
上限」调小（如 15）。页面写「没有可用的解码器」时，说明这台机器既没有 PyAV 也没有 ffmpeg.exe：
「pip install av」即可（正常装 faster-whisper 就会带上）。不想上传云端的话，同一张卡片上的
「不提取，直接本机识别出双语字幕」会把视频整段交给本机模型跑精修。

**打不开麦克风（`-9999 / MME error 1`）** — 给视频配音幕用「系统声音」（回环实测可用）；
要麦克风请选 WASAPI 麦（本机设备 15），或更新声卡驱动。

**选「系统声音」但没字幕** — ① 播放软件必须真的在出声且输出到所选回环设备
（自动检测会帮你挑）；② 静音不出字幕是特性；③ 看控制中心顶部进度条的"待识别/已识别"
与左侧设备电平提示定位；`run.bat check` 可列出全部回环设备。

**悬浮窗显示"连接不上浏览器版"** — 控制中心的 Streamlit 进程退出后，跟随窗重试 15 次自动退出；
重启 `run.bat web` 即可恢复。

**在线翻译偶尔原样返回** — 免费服务不稳，已在多服务商间自动回退；求稳用
`openai`/`baidu` 后端。

**faster-whisper 首次下载模型慢/失败** — 已默认走 hf-mirror.com 镜像（并禁用 Windows
需要开发者模式的符号链接缓存）。仍失败可自己设环境变量 `HF_ENDPOINT`，或临时切
`openai-whisper` 后端（权重此前已下到 `models/`）。
